# Startup, TradersHub and fundamentals follow-up

The TradersHub screenshot showed a failed request, not an empty-community success. A fresh owner sign-in loaded the current post. Reads previously waited on token refresh for the last 30 seconds of an otherwise valid JWT; a slow refresh therefore blocked every feed dependency. They now use that still-valid in-memory token while refresh runs. Expired/revoked sessions still fail and every backend signature, live-session, owner and SQL check remains in force. Only idempotent reads retry one transient network/502/503/504 or short application throttle; writes, 401/403 and bot challenges do not retry. Token refresh no longer restarts the entire feed through object-identity changes.

Account display hints now survive reopening for up to 24 hours, keyed to the live verified account. Profile refresh replaces them in the background. Subscription expiry remains enforced and paid API authorization stays server-side. Explicit logout/account switch clears these hints and all private queries while retaining only the existing allowlisted public research queries. No password or JWT is persisted.

Publisher financials previously used a query namespace excluded from persistent research caching. They now join the public cache. Stock entry starts the same public financial queries before the Fundamentals section opens; cached data remains visible if a background refresh fails. First-ever visits still require a download. Existing monthly allowance checks and published-period/source validation remain unchanged.

Collector run 88 saved seven artifacts and processed eleven extractions but failed on four publisher tab timeouts and two Centum HTTP errors. The renderer now explicitly selects an observed tab if hydration ignores its URL, verifies the resulting selection, and still fails missing/wrong views. Generic crawl receipts distinguish removed 404/410 links from connection, auth and permission errors; they retain private failure checkpoints and never create replacement financial values. Finite transfer/time caps and source permissions remain unchanged. Existing historical failed runs remain historical failures.

Language choice: existing JavaScript identity/data transports, React frontend and Python Selenium collector. This is a targeted repair using existing runtimes; no new service and no claim of completing the separately gated Go rewrite. TanStack Query's [cache and background-refresh model](https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults) supports showing saved data while refreshing it. [Publisher Financials](https://kenyanstocks.com/stock/nse/SCOM?tab=Financials) exposes the tab controls verified by the renderer.
